# Current State — tutu-clone

Снимок состояния проекта после интеграции «Плана «Б»» с `mcp.tutu.ru/mcp`
и доводки UI результатов поиска.

## Цель и границы проекта

- **Реальная обвязка вокруг MCP (`mcp.tutu.ru/mcp`) нужна только для одной
  страницы — «Срочно добраться» / «План «Б»» (`/urgent`,
  компонент `UrgentTravel.tsx`).** Это единственная часть продукта, где
  должна быть настоящая логика поверх реальных данных.
- **Всё остальное (главная `/` и все её блоки — hero-поиск, карусели
  предложений, отели, промо-баннеры) — фейковый лендинг.** Это витрина для
  визуального контекста/навигации, реальным бэкендом её обвешивать не
  планируется. Хардкод там можно не трогать.

## Стек

- Next.js 16 (App Router, Turbopack), React 19, TypeScript
- Tailwind CSS v4 + shadcn/ui примитивы
- Шрифт: Golos Text (замена проприетарного Tutu Sans)
- Бэкенд: один read-only route handler (`src/app/api/urgent-travel/search/route.ts`),
  проксирующий поиск Плана «Б» в публичный `mcp.tutu.ru/mcp` (JSON-RPC поверх
  HTTP, без авторизации, без ключей). Ни БД, ни `.env`, ни auth — на главной
  странице всё так же живёт на локальном `useState`.

## План «Б» (`/urgent`) — интегрирован с `mcp.tutu.ru/mcp`

### Форма

- **Маршрут и срок**: города Откуда/Куда (комбобоксы с фильтром по вводу),
  день (следующие 7 дней), время. Справа от заголовка секции — подпись
  «Когда надо быть на месте», поясняющая, что День+Время — это дедлайн
  прибытия, а не время вылета.
- **Быстрый выбор города**: под каждым полем Откуда/Куда, ниже выпадающего
  списка — статичный серый блок с двумя маленькими прямоугольными кнопками
  «Санкт-Петербург» / «Москва» (`QUICK_PICK_CITIES` в `UrgentTravel.tsx`),
  клик сразу подставляет город. Видны всегда, не только при открытом списке.
- **Транспорт**: тумблеры самолёт/поезд/автобус/электричка.
- **Условия**: пересадки (есть/нет), бюджет (без ограничений / до 5–20 тыс ₽).
- **Валидация**: Откуда/Куда/День/Время — обязательные поля; при пустом
  сабмите (`submitAttempted` в `UrgentTravel.tsx`) каждое подсвечивается
  красной рамкой (`.ut-input--invalid`) и получает inline-сообщение под
  собой (`.ut-field-error`, цвет — `--color-error`). Раньше не подсвечивалось
  вообще ничего (текст ошибки был того же цвета, что и обычный, а День/Время
  вообще не проверялись) — вместе с этим День и Время стали обязательными,
  без конкретного момента дедлайна невозможно корректно искать по диапазону
  дат (см. ниже).

### Поиск

`UrgentTravel.tsx` на submit держит `status: idle|loading|done|error` и шлёт
`POST /api/urgent-travel/search`. Загрузка длится не меньше 700 мс
(`MIN_LOADING_MS`) даже если API ответил мгновенно — чтобы поиск ощущался
настоящим — и на это время вместо результатов показывается скелетон
(пульсирующие серые полоски в той же сетке, что и реальная таблица, подпись
«Ищем варианты…»).

Роут вызывает `search_multitransport` на `mcp.tutu.ru/mcp` (публичный,
read-only, без авторизации). Два осознанных отступления от «идеального»
плана — MCP физически не даёт большего:

- **`CITIES` в `UrgentTravel.tsx` остаётся статичным списком из 24 городов.**
  У MCP нет тула для live city-search (`tutu://geo` — офлайн-снепшот на
  2 города, помечен как неполный). Реальный резолвинг города происходит
  внутри самого поиска — `meta.from`/`meta.to` в ответе эхом возвращают,
  что сервер понял; если расходится с введённым текстом, показывается
  строка «Уточнили маршрут: …».
- **Дедлайна («успеть к сроку») MCP не поддерживает** — только
  `departure_date` на один конкретный день. Раньше в качестве этого
  параметра ошибочно передавался сам день дедлайна — то есть при дедлайне
  «21 августа» искались только рейсы, ВЫЛЕТАЮЩИЕ 21 августа, а не рейсы,
  успевающие к этой дате (самый ранний вылет сегодня вечером в выдачу вообще
  не попадал). Исправлено: `searchUrgentTravel()` (`earliestDate` — сегодня,
  `deadlineDate` — выбранный день) теперь параллельно запрашивает
  `search_multitransport` на каждую дату от сегодня до дня дедлайна
  включительно, объединяет варианты и уже потом отсекает те, что прибывают
  позже дедлайна (по `arrival_at`, с учётом часового пояса города
  назначения — не браузера). Если после фильтра пусто — показывает
  ближайшие по времени варианты с пометкой `deadlineMissed: true` и
  предупреждением в UI; в этом случае карточка «Быстрее всего» перестаёт
  означать «короче по длительности» (это может быть рейс, который вылетает
  поздно ночью и всё равно прибывает позже всех) и вместо этого показывает
  вариант с самым ранним временем прибытия, с другим текстом бейджа —
  «Прибудет раньше всех».

### Результаты

Таблица: Транспорт | Отправление | Прибытие | В пути | Цена | (бейдж) | Действие.

- **Дата и время — по местному времени точки**, не браузера: `formatLocal()`
  в `urgent-travel-search.ts` читает цифры прямо из ISO-строки MCP (у неё
  всегда оффсет своей станции), не пропуская через `Date()` — конвертация
  тайком пересчитала бы всё в часовой пояс браузера. Формат: «21 авг, 23:26».
- **Название вокзала/терминала** — мелкой подписью под временем
  (`stationLabel()` вычищает внутренние id и IATA-коды из `legs[].from/to`,
  оставляя, например, «Ленинградский вокзал» или «Шереметьево, терм. B»).
- **Карточек-лидеров теперь две** (было три): «Быстрее всего» и
  «Дешевле всего». **«Надёжнее всего» убрано полностью** — из UI и из
  логики (`RELIABILITY_ORDER`/`reliableOffer` в `urgent-travel-search.ts`
  удалены).
- Обе карточки показывают готовую брендированную картинку-бейдж
  (`badge-fastest.png` / `badge-cheap.png`) в отдельной колонке
  фиксированной ширины (`--ut-badge-col`) между ценой и кнопкой «Выбрать» —
  колонка не «плавает» в зависимости от того, есть ли в строке бейдж.
- **Строка «Быстрее всего» вдобавок подсвечена** лёгким лиловым фоном
  целиком (`.ut-row--priority`, `background: var(--color-accent-soft)`) —
  визуальный приоритет по требованию заказчика.
- **Колонка «Транспорт» с отступом слева** (~1rem, `.ut-cell--mode` /
  `.ut-board-head-mode`) — текст не упирается в границу лиловой заливки.
- **Все найденные варианты показываются сразу** — кнопки/тумблера
  «Показать ещё» больше нет, `extraRows` рендерятся полностью без
  сворачивания.
- Колонка «Действие» (`--ut-action-col`) тоже фиксированной ширины по той
  же причине: `auto`-колонка в CSS Grid сайзится по контенту, а в шапке
  там sr-only текст, в строках — настоящая кнопка, из-за чего без фикса
  шапка и строки расходились в ширине остальных колонок.
- Кнопки «Выбрать» открывают `checkoutUrl ?? searchResultsUrl` — реальные
  страницы оформления/поиска tutu.ru — в новой вкладке.

### FAQ

`UrgentTravelFaq.tsx` — 5 вопросов на нативных `<details>/<summary>`
(работает без JS) сразу под таблицей результатов, плюс `<script
type="application/ld+json">` с разметкой `FAQPage` для SEO — как у
настоящего Tutu.

## Прод-полировка (перед сдачей хакатона)

- **Метаданные** (`layout.tsx`) больше не называют проект «клоном/учебной
  копией» — раньше `<title>`/`description` буквально это говорили, что
  подрывало питч ещё до того, как судья увидел саму фичу.
- Убран неиспользуемый scaffold от `shadcn init`: `src/components/ui/button.tsx`
  (нигде не импортировался), дефолтная тема shadcn в `globals.css` (сайдбар/
  чарт/card/popover токены — не использовались нигде, кроме удалённого
  button.tsx), и зависимости `@base-ui/react`, `class-variance-authority`,
  `lucide-react`, `shadcn` из `package.json` (нигде в рантайме не
  использовались). `.dark`-тема тоже убрана — в проекте нет тёмной темы.
- Единственная реальная ошибка ESLint (`<a href="/">` вместо `next/link`
  в хлебных крошках Плана «Б») — исправлена.

## Итог

Главная страница — витрина, её трогать не планируется. План «Б» полностью
на реальных данных: маршрут/срок/транспорт/пересадки/бюджет из формы
уходят в `/api/urgent-travel/search` → `mcp.tutu.ru/mcp`, результаты — с
локальным временем/датой, вокзалами, живыми ссылками на оформление, без
скрытых вариантов за кнопкой-раскрывашкой.
